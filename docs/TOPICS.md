# 주제 모음

날짜별 노트에 흩어진 목록 항목을 위키링크의 대상으로 묶어 읽는 뷰입니다. 원문을 복제하거나 별도 주제 파일을 만들지 않습니다.

```markdown
- 오늘 떠오른 아이디어 [[Foo]]
  - 살펴볼 자료
  - 다음에 해볼 일
- 다른 기록
```

‘주제 모음’에서 Foo를 선택하면 첫 항목과 두 하위 항목이 한 카드로 나타납니다. 다른 노트의 Foo 항목들도 같은 화면에 표시됩니다. ‘다른 기록’은 포함하지 않습니다. 기본 leader 명령은 `Space v c`이며 일반 단축키도 설정에서 `주제 모음 열기`에 지정할 수 있습니다.

## 포함 규칙

- `-`, `*`, `+`, 체크박스, 번호 목록에서 **해당 항목의 첫 물리 행에 있는** `[[...]]`를 주제로 인식합니다. 줄 바꿈된 뒤의 일반 문장 링크는 새 카드를 만들지 않습니다.
- 카드에는 항목 전체의 Markdown 하위 구조를 포함합니다. 하위 목록, 들여쓴 연속 문단, 코드 블록 등이며 같은 깊이의 다음 항목은 제외합니다.
- 하위 항목의 링크는 그 하위 항목을 선택합니다. 부모가 주제 링크 없이 자식에만 `[[Foo]]`가 있으면 부모 전체를 수집하지 않습니다.
- 한 항목에 여러 주제가 있으면 각 주제에 포함합니다. 동일 대상을 반복해서 쓰면 그 항목은 한 번만 포함합니다.
- 부모와 자식 모두 같은 주제로 표시했다면 각각 카드가 됩니다. 따라서 자식 내용은 부모 카드 안에서도 보일 수 있습니다.
- 일반 문장, 코드 펜스·인라인 코드·들여쓴 코드, HTML 주석, 이스케이프된 문법, 일반 Markdown 링크의 URL은 주제 항목으로 수집하지 않습니다.
- 주제 노트가 없어도 `[[Foo]]`는 `Foo`라는 주제로 동작합니다. `[[Foo|표시 이름]]`은 표시 이름이 아닌 Foo로 묶습니다.
- 기존 노트로 연결된 링크는 노트 UUID로 묶습니다. 주제 노트 이름을 바꿔도 같은 그룹을 유지하며 새 제목을 표시합니다. 같은 제목의 노트가 여럿이면 기존 링크 규칙처럼 제목만으로 임의의 노트를 고르지 않습니다.
- core를 통해 대상 노트를 삭제하면 참조를 UUID로 고정합니다. 대상이 삭제돼도 그룹은 유지하고 가능한 경우 링크의 표시 이름을 사용합니다. 원본 노트가 휴지통에 들어가면 해당 카드들은 제외되고 복원하면 다시 나타납니다.

## 화면

주제 이름 검색, 주제별 노트/카드 개수, 노트 생성일 최신순/오래된순을 제공합니다. 같은 노트 안에서는 원문 행 순서를 유지합니다. 카드 날짜는 노트 생성일이며 bullet 작성일이나 노트 제목 속 날짜를 추정하지 않습니다.

카드 헤더의 원본 버튼은 해당 노트의 bullet 시작 행을 Live Preview로 열고 커서를 이동합니다. 주제 노트가 존재하면 별도의 ‘주제 노트 열기’도 제공합니다. 선택 주제·정렬·페이지는 다른 뷰나 원본을 보고 돌아와도 유지하며 Vault 전환 시 초기화합니다. 카드 본문은 읽기 전용이고 수정은 원본에서 합니다.

기본 페이지는 50개 카드입니다. 긴 카드의 하위 내용을 임의로 자르지 않습니다. 좁은 창에서는 주제 선택 목록을 카드 위로 배치합니다. 카드의 `foltra-query`는 자동 실행하지 않고 코드로 표시합니다. Markdown의 기존 HTML/외부 이미지 차단 규칙을 재사용합니다.

## 코어와 CLI

`topics.list`와 `topics.blocks`는 읽기 전용 명령입니다. Foltra CLI와 GUI가 같은 코드를 사용합니다.

```sh
foltra --vault /path/to/vault topics list
foltra --vault /path/to/vault topics blocks --args '{"topic":"name:Foo","offset":0,"limit":50,"descending":true}'
```

`topic`은 `topics.list`가 반환한 `id`를 그대로 전달합니다. 없는 주제의 예시는 `name:Foo`이고, 기존 노트 대상은 `note:<uuid>`입니다. 이름에서 ID를 직접 합성하는 것보다 목록의 값을 사용하는 것이 안전합니다.

`topics.list`는 `{id,title,noteId,blockCount,noteCount}[]`를 반환합니다. `topics.blocks`는 `{topic,blocks,total,offset,limit}`를 반환하고 카드에는 `{noteId,noteTitle,revision,createdAt,updatedAt,line,endLine,body}`가 있습니다. 행 번호는 노트 **본문 기준 1부터 시작**합니다. `limit`은 1–100, 기본 50이고 `offset` 기본값은 0입니다. 없는 주제는 빈 결과를 반환합니다.

## 구현과 한계

`crates/core/src/topics.rs`에서 [pulldown-cmark의 위키링크와 소스 범위](https://docs.rs/pulldown-cmark/0.13.4/pulldown_cmark/)를 사용해 목록 경계를 읽습니다. 기존 정규화/백링크와 같은 `wiki::resolve_note`로 대상을 해석합니다. 한 조회에서 노트 원본과 범위를 보관하며, 선택 페이지의 본문만 응답용으로 만듭니다. 원본 파일, 기존 revision, 백업 형식은 바꾸지 않습니다.

`useTopics`는 노트 ID/revision이 바뀌면 다시 조회하며 주제·페이지·Vault가 바뀐 뒤 도착한 이전 응답은 무시합니다. 앱 내부 저장 직후와 외부 CLI 변경의 기존 3초 snapshot 갱신에 연결됩니다.

조회마다 활성 노트를 스캔·파싱합니다. 아직 증분 인덱스, 대형 vault 벤치마크, 안정적인 block UUID, 카드 안에서 직접 수정하는 기능은 없습니다. 행 위치는 해당 revision의 위치이므로 외부에서 원문을 수정하는 순간과 원본 열기가 겹치면 다음 갱신 전까지 낡은 위치일 수 있습니다. native 입력·IME 검증과 대형 문서 검증은 별도입니다.
