# 주제 모음

날짜별 노트에 흩어진 문단과 목록 항목을 위키링크의 대상으로 묶어 읽는 뷰입니다. 원문을 복제하거나 별도 주제 파일을 만들지 않습니다.

```markdown
- 오늘 떠오른 아이디어 [[Foo]]
  - 살펴볼 자료
  - 다음에 해볼 일
- 다른 기록
```

‘주제 모음’에서 Foo를 선택하면 첫 항목과 두 하위 항목이 한 카드로 나타납니다. 다른 노트의 Foo 항목들도 같은 화면에 표시됩니다. ‘다른 기록’은 포함하지 않습니다. 기본 leader 명령은 `Space v c`이며 일반 단축키도 설정에서 `주제 모음 열기`에 지정할 수 있습니다.

## 포함 규칙

- 일반 문단은 어느 줄에든 `[[...]]`가 있으면 문단 전체를 한 카드로 수집합니다. 빈 줄로 나뉜 다음 문단은 포함하지 않습니다. 제목과 인용문 안의 문단도 해당 블록만 수집하며 제목 아래 섹션 전체를 묶지는 않습니다.
- 목록 뒤에서 들여쓰기를 해제하고 쓴 문단은 빈 구분 줄이 없어도 별도 카드로 수집합니다. 편집기/읽기 모드처럼 목록 카드에서도 그 문단을 제외합니다. 명시적으로 들여쓴 연속 내용과 여러 줄에 걸친 인라인 문법은 유지합니다.
- `-`, `*`, `+`, 체크박스, 번호 목록에서 **해당 항목의 첫 물리 행에 있는** `[[...]]`를 주제로 인식합니다. 명시적으로 들여쓴 연속 문장의 링크는 새 카드를 만들지 않습니다.
- 카드에는 항목 전체의 Markdown 하위 구조를 포함합니다. 하위 목록, 들여쓴 연속 문단, 코드 블록 등이며 같은 깊이의 다음 항목은 제외합니다.
- 하위 항목의 링크는 그 하위 항목을 선택합니다. 부모가 주제 링크 없이 자식에만 `[[Foo]]`가 있으면 부모 전체를 수집하지 않습니다.
- 한 블록에 여러 주제가 있으면 각 주제에 포함합니다. 동일 대상을 반복해서 쓰면 그 블록은 한 번만 포함합니다.
- 부모와 자식 모두 같은 주제로 표시했다면 각각 카드가 됩니다. 따라서 자식 내용은 부모 카드 안에서도 보일 수 있습니다.
- 표 셀, 코드 펜스·인라인 코드·들여쓴 코드, HTML 주석, 이스케이프된 문법, 일반 Markdown 링크의 URL은 주제 항목으로 수집하지 않습니다.
- 주제 노트가 없어도 `[[Foo]]`는 `Foo`라는 주제로 동작합니다. `[[Foo|표시 이름]]`은 표시 이름이 아닌 Foo로 묶습니다.
- 기존 노트로 연결된 링크는 노트 UUID로 묶습니다. 주제 노트 이름을 바꿔도 같은 그룹을 유지하며 새 제목을 표시합니다. 같은 제목의 노트가 여럿이면 기존 링크 규칙처럼 제목만으로 임의의 노트를 고르지 않습니다.
- core를 통해 대상 노트를 삭제하면 참조를 UUID로 고정합니다. 대상이 삭제돼도 그룹은 유지하고 가능한 경우 링크의 표시 이름을 사용합니다. 원본 노트가 휴지통에 들어가면 해당 카드들은 제외되고 복원하면 다시 나타납니다.

## 화면

주제 이름 검색, 주제별 노트/카드 개수, 노트 생성일 최신순/오래된순과 사용자 지정 정렬을 제공합니다. 날짜 정렬에서는 같은 노트 안의 원문 행 순서를 유지합니다. 카드 날짜는 노트 생성일이며 블록 작성일이나 노트 제목 속 날짜를 추정하지 않습니다.

카드 헤더의 원본 버튼은 해당 노트의 블록 시작 행을 Live Preview로 열고 커서를 이동합니다. 주제 노트가 존재하면 별도의 ‘주제 노트 열기’도 제공합니다. 선택 주제·정렬·페이지는 다른 뷰나 원본을 보고 돌아와도 유지하며 Vault 전환 시 초기화합니다. 카드 본문은 읽기 전용이고 수정은 원본에서 합니다.

카드 왼쪽의 손잡이를 드래그하면 위/아래 삽입선을 표시하고, 놓는 즉시 사용자 지정 순서를 저장합니다. 날짜 정렬에서도 드래그할 수 있으며 현재 순서에서 사용자 지정으로 전환합니다. 손잡이에 포커스한 뒤 Alt+↑/↓로 같은 페이지의 이전/다음 카드와 순서를 바꿀 수도 있습니다. 본문 텍스트 선택과 링크 클릭은 기존대로 동작합니다. 드래그 중 이전/다음 페이지 버튼 위에 잠시 머무르면 해당 페이지로 넘어가 카드를 놓을 수 있습니다.

순서는 주제별로 `.foltra/topic-order.json`에 저장하며 앱을 다시 열어도 유지됩니다. 날짜 정렬로 전환해도 사용자 지정 순서를 삭제하지 않습니다. 새 카드는 기존 순서 뒤에 붙습니다. 순서를 바꾸어도 노트 본문과 revision은 변경하지 않으며 vault 내 다른 데이터와 함께 백업/복원됩니다.

기본 페이지는 50개 카드입니다. 긴 카드의 하위 내용을 임의로 자르지 않습니다. 좁은 창에서는 주제 선택 목록을 카드 위로 배치합니다. 카드의 `foltra-query`는 자동 실행하지 않고 코드로 표시합니다. Markdown의 기존 HTML/외부 이미지 차단 규칙을 재사용합니다.

## 코어와 CLI

`topics.list`와 `topics.blocks`는 읽기 전용이며 `topics.reorder`는 카드 표시 순서만 저장하는 명령입니다. Foltra CLI와 GUI가 같은 코드를 사용합니다.

```sh
foltra --vault /path/to/vault topics list
foltra --vault /path/to/vault topics blocks --args '{"topic":"name:Foo","offset":0,"limit":50,"descending":true}'
```

`topic`은 `topics.list`가 반환한 `id`를 그대로 전달합니다. 없는 주제의 예시는 `name:Foo`이고, 기존 노트 대상은 `note:<uuid>`입니다. 이름에서 ID를 직접 합성하는 것보다 목록의 값을 사용하는 것이 안전합니다.

`topics.list`는 `{id,title,noteId,blockCount,noteCount}[]`를 반환합니다. `topics.blocks`는 `{topic,blocks,total,offset,limit,sort,orderRevision}`를 반환하고 카드에는 `{id,noteId,noteTitle,revision,createdAt,updatedAt,line,endLine,body}`가 있습니다. 행 번호는 노트 **본문 기준 1부터 시작**합니다. `limit`은 1–100, 기본 50이고 `offset` 기본값은 0입니다. 없는 주제는 빈 결과를 반환합니다.

`topics.blocks`의 `sort`는 `newest`, `oldest`, `custom`이며 생략하면 저장한 사용자 지정 순서, 없으면 최신순을 사용합니다. 기존 `descending` 인자도 지원하며 명시적인 `sort`가 우선합니다.

`topics.reorder`는 `{topic,source,target,placement,sort,expectedRevision}`을 받습니다. `source`와 `target`은 조회 응답의 카드 `id`, `placement`는 `before`/`after`, `sort`는 드래그를 시작한 정렬, `expectedRevision`은 `orderRevision`입니다. 페이지를 넘겨도 같은 전체 컬렉션의 revision을 사용합니다. 순서나 원본이 바뀌었으면 conflict로 거절하며 새 revision으로 자동 덮어쓰지 않습니다. 카드 `id`는 현재 소스 위치를 가리키므로 영구 블록 UUID로 사용하지 않습니다.

## 구현과 한계

`crates/core/src/topics.rs`에서 [pulldown-cmark의 위키링크와 소스 범위](https://docs.rs/pulldown-cmark/0.13.4/pulldown_cmark/)를 사용해 문단·제목·목록 경계를 읽습니다. 기존 정규화/백링크와 같은 `wiki::resolve_note`로 대상을 해석합니다. 한 조회에서 노트 원본과 범위를 보관하며, 선택 페이지의 본문만 응답용으로 만듭니다. 읽기와 정렬은 노트 원본 및 revision을 바꾸지 않습니다. 순서 메타데이터는 기존 백업의 files에 포함합니다.

`useTopics`는 노트 ID/revision이 바뀌면 다시 조회하며 주제·페이지·Vault가 바뀐 뒤 도착한 이전 응답은 무시합니다. 앱 내부 저장 직후와 외부 CLI 변경의 기존 3초 snapshot 갱신에 연결됩니다. workspace의 topicOrderRevision으로 다른 창/CLI의 순서 변경도 감지합니다.

조회마다 활성 노트를 스캔·파싱합니다. 아직 증분 인덱스, 대형 vault 벤치마크, 안정적인 block UUID, 카드 안에서 직접 수정하는 기능은 없습니다. 행 위치는 해당 revision의 위치이므로 외부에서 원문을 수정하는 순간과 원본 열기가 겹치면 다음 갱신 전까지 낡은 위치일 수 있습니다. native 입력·IME 검증과 대형 문서 검증은 별도입니다.

순서 추적은 노트 ID, 원문 시작 행, 카드 내용/첫 줄의 해시를 사용합니다. 위키링크의 제목·alias 변화는 해시에서 정규화하고, 내용 일치 → 첫 줄 일치 → 일치한 이웃 사이의 동일 개수 블록 순서로 대응시킵니다. 앞쪽 일반 문단 삽입과 같은 위치의 내용 수정은 이 방식으로 추적합니다. 영구 블록 UUID가 없으므로 대량 재작성, 동일 내용 블록의 삽입/삭제 등 모호한 편집에서는 기존 블록을 완벽하게 식별할 수 없습니다. 대응되지 않는 카드는 뒤에 추가되며, 필요하면 다시 드래그할 수 있습니다. 미생성 주제 노트의 생성/이름 변경 시 이름 기반 순서 키를 노트 UUID로 옮기는 작업은 원본 쓰기와 같은 transaction에서 처리합니다.
