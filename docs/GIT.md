# Git 동기화 확장

설정 → 확장에서 **플러그인 사용**에 최초 한 번 동의한 뒤 **Git 동기화**를 설치하고 활성화합니다. 확장 설정에서 비어 있는 개인 Git 저장소 주소와 브랜치를 입력하고 **연결 설정 저장**을 누릅니다. 앱의 확인 창에서 실제 목적지와 전송 범위를 확인한 뒤 연결합니다. 연결만으로 업로드하지 않으며, **지금 동기화**로 시작합니다.

- 동기화: `Cmd+Shift+s` / `<leader>gs`
- 동기화 화면 열기: `<leader>go`
- 단축키는 다른 확장 명령처럼 설정에서 변경할 수 있습니다.
- 자동 동기화는 기본 꺼짐입니다. 켜면 앱 실행 중 설정한 간격(1~1440분, 기본 5분)에 맞춰 검사합니다. 충돌·실패·중단 상태에서는 수동 확인을 기다립니다.

## 저장소와 인증

현재 배포 대상인 macOS에서는 시스템 Git이 필요합니다. HTTPS 주소는 Git의 macOS Keychain 인증을 사용하고, SSH 주소는 SSH agent와 이미 등록된 호스트 키를 사용합니다. 미리 인증을 설정해야 하며, 앱에서 암호나 토큰을 저장하거나 터미널 입력을 요구하지 않습니다. URL에 사용자명·비밀번호·토큰을 포함할 수 없습니다. 사용자 Git 설정의 임의 helper·별칭·훅·SSH 설정 파일은 실행하지 않습니다.

`https://host/user/vault.git`, `git@host:user/vault.git`, `ssh://git@host/user/vault.git` 형식과 기존 로컬 bare 저장소의 절대 경로를 지원합니다. 로컬 저장소에는 실행 훅·include·alternate 객체 저장소 등의 설정이 없어야 합니다. Git 저장소 생성이나 GitHub 저장소 생성·로그인은 자동으로 수행하지 않습니다. 다른 프로젝트 저장소를 지정하지 말고 Foltra 전용 저장소를 사용하세요.

두 번째 기기에서는 예제를 포함하지 않은 **빈 vault**를 만든 뒤 같은 저장소에 연결합니다. 첫 동기화가 원격 vault의 ID와 데이터를 가져옵니다. 서로 다른 ID를 가진 비어 있지 않은 vault는 자동으로 합치지 않습니다.

## 동기화 대상

노트, 폴더, DB 스키마와 행, 이미지 첨부파일, 휴지통, 주제 모음 순서, vault 식별 정보가 대상입니다. 기기 설정, 인증정보, 확장 패키지·설정·실행 승인, 인덱스·캐시는 보내지 않습니다. 첨부파일은 다른 노트나 휴지통에서 참조할 수 있으므로 합집합으로 보존합니다.

실제 vault를 Git으로 checkout하지 않습니다. `.foltra/local/git/` 아래 별도 bare 저장소와 작업 상태를 사용하며, 이미 존재하는 사용자의 `.git`도 변경하지 않습니다. 확장을 비활성화하거나 삭제해도 노트와 로컬 Git 이력은 남습니다. Git은 암호화된 동기화가 아니며 원격 저장소 접근 권한에 따라 파일이 보입니다.

## 충돌과 복구

파일 단위 3-way 병합을 사용합니다. 서로 다른 파일의 변경은 합치고, 같은 파일의 양쪽 변경 또는 수정 대 삭제는 선택을 기다립니다. 충돌 화면에서 비교 내용을 보고 **내 변경** 또는 **원격 변경**을 고릅니다. 문장 단위 자동 병합은 하지 않습니다. 40개를 초과한 충돌은 처음 40개를 미리 보여 주고 전체 선택을 제공합니다.

두 원본은 로컬 Git refs에 보존합니다. 선택 결과가 폴더·DB 스키마·행 관계를 깨뜨리면 적용하지 않습니다. 다운로드 중 로컬 원본이 변경되어도 덮어쓰지 않고 다시 동기화를 요청합니다. 아직 저장되지 않은 편집 초안은 편집기에 남고, 충돌 시 기존 사본 저장 기능을 사용할 수 있습니다.

원격 전송에 실패하면 **로컬 반영 완료 · 원격 전송 대기**로 구분합니다. 네트워크나 원격 변경을 확인한 뒤 다시 동기화하면 됩니다. force push는 하지 않으며, 연결했던 원격 브랜치가 삭제된 경우 자동으로 재생성하지 않습니다. 최근 20개 작업 상태를 기기에 보관하고 화면에는 최근 5개를 표시합니다. Git 이력은 완전 삭제한 휴지통의 과거 내용도 포함할 수 있습니다.

## 실행 한도와 CLI

Git 네트워크 동안 vault 쓰기 잠금을 유지하지 않습니다. 수신된 파일의 경로·타입·해시·ID·DB/폴더 관계를 검증한 뒤 현재 revision과 일치하는 경우에만 기존 journal로 일괄 적용합니다. 심볼릭 링크·실행 파일·하위 모듈은 허용하지 않습니다. 현재 한도는 snapshot 10,000개 파일/128 MiB, 텍스트 파일 16 MiB, 이미지 10 MiB, Git 객체 저장소 256 MiB, Git 명령당 60초입니다. 용량을 넘기면 원본을 보존하고 오류를 표시합니다.

CLI와 에이전트는 동일한 `git.status`, `git.configure`, `git.sync`, `git.resolve` 명령을 사용할 수 있습니다. `git.configure`는 `git.status`의 `configRevision`을 `expectedRevision`으로 받습니다. `git.resolve`는 현재 `jobId`와 파일별 `choices` (`local`/`remote`) 또는 `all`을 받습니다. 상세 JSON 인자는 `commands.list`에 있습니다. CLI의 `git.sync`는 완료까지 기다리며 별도 데몬은 실행하지 않습니다.
