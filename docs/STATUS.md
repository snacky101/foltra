# 개발 현황 · 2026-09-15

현재 결과물은 **Foltra 0.1 로컬 개발 프리뷰**입니다. `snack-note`와 독립된 Git 저장소이며, macOS용 Tauri 앱과 headless CLI를 빌드했습니다. 제품 전체를 완료하거나 버그·보안 문제·지연이 없다고 보증하는 단계는 아닙니다.

## 확인한 결과

macOS에서 `npm test`: **112개 통과** — core 계약 50개, 실제 CLI 프로세스 4개, 프런트엔드 58개. Vault 이름 기반 경로 제안, 한글/IME 명령 키 보정, 대소문자 구분·충돌, 기존 단축키 설정 호환 검증을 포함합니다. Vim 기본 설정과 editorMode 저장, 실제 Vim Ex parser의 무인자 명령·bang·범위 거절, 저장 실패 시 닫기 방지, Live Preview 원문 보존, 최근 vault 목록, 실제 CLI를 사용하는 예제 본문 연결 회귀 검증을 포함합니다.

테스트는 DB 행의 노트 비종속성, 본문 생성/삭제 관계, revision 충돌, 다중 writer, 링크 제목 변경, 코드 예제 보존, typed query, 검색 인덱스 재생성, 휴지통, 복구 journal, snapshot 복원, 잘못된 경로·설정·theme 입력, 플러그인 headless 실행을 포함합니다. 일부만 통과한 stub 결과가 아니라 실제 임시 디렉터리에 읽고 쓰는 계약 테스트입니다.

`npm run check`: TypeScript 타입 검사, 프로덕션 프런트엔드 빌드, Rust format, 전체 workspace 및 test target Clippy 통과. `npm run tauri -- build --debug`: macOS `.app` 생성 성공. npm 설치 시 dependency audit 0건으로 반환됐지만 독립적인 보안 감사 결과를 의미하지 않습니다.

브라우저에서 실제 CLI 코어에 연결한 UI를 사용해 vault 생성, 예제 데이터, 노트 저장과 한글 텍스트 삽입, 링크/백링크 표시, DB 상태 수정, 행 본문 생성, 확장·테마 JSON 설치, 사용자 단축키 저장과 확장 template 실행을 확인했습니다. CLI에서 추가한 노트가 열린 GUI에 반영되는 흐름도 확인했습니다. 샘플 vault는 저장소의 `dev-vault/`이며 Git에서 제외합니다.

이번 변경의 브라우저 확인은 별도 임시 vault로 수행했습니다. 일반 입력과 Vim `:w`/`:q`/`:wq`, Live Preview 표·쿼리·위키링크, 예제 행의 본문 열기, vault 생성/오류 유지/최근 목록 전환, 양쪽 경계 드래그와 너비 복원, 내용 검색 12개 결과의 방향키·Enter·빈 결과, 밝은/어두운 테마의 선택 목록과 달력을 확인했습니다. live/source 전환 후 실행 취소가 유지되는 것도 확인했습니다. 실제 확인 결과는 `test-results/`의 로컬 검증 기록과 스크린샷에 남깁니다. 기본 Personal vault의 누락된 예제 본문은 core의 revision 조건을 통해 연결했고, 기존 노트와 대상 외 행의 파일 해시가 바뀌지 않았음을 확인했습니다.

macOS 제목 표시줄은 기존 앱 헤더에 native 창 버튼을 겹치는 `Overlay` 방식으로 설정하고 별도 제목을 숨겼습니다. native UI 검증 도구가 `NODE_REPL_TRUSTED_SERVICES` 런타임 오류로 연결되지 않아 실제 창 배치·창 드래그는 미검증입니다. 브라우저의 레이아웃 확인과 native bundle 빌드 성공을 macOS 시각 검증으로 계산하지 않습니다. 실행 중인 이전 앱은 종료 후 새 빌드로 열어야 native 설정이 반영됩니다. 시스템 폴더 선택 창은 OS에서 제공합니다.

**키보드 검증의 한계:** 테스트 브라우저에서 Escape가 페이지 이벤트로 전달되지 않았고 브라우저 측 Vim 관련 HUD가 나타났습니다. 정확한 간섭 원인은 확정하지 않았습니다. Escape와 leader 명령 라우팅 일부는 페이지에 KeyboardEvent를 직접 보내 확인했습니다. 이것은 물리 키 입력이나 native 앱의 실제 IME 검증을 대체하지 않습니다. `insertText`로 한글을 넣은 결과도 조합 입력 검증으로 계산하지 않습니다.

**성능 검증의 한계:** 대형 vault 벤치마크와 p95 지연 목표는 측정하지 않았습니다. 그래프 최대 120개, DB 화면 페이지 100행, 쿼리 최대 500행입니다. snapshot은 3초마다 전체 원본을 스캔하며 DB query는 메모리 필터입니다. editor chunk가 약 647KB(minified, gzip 약 221KB)여서 Vite의 500KB 경고가 남습니다. 경고를 숨기기 위해 기준값을 올리지 않았습니다.

**출시 검증의 한계:** debug 빌드이며 서명·공증·자동 업데이트·배포는 수행하지 않았습니다. `.app`를 열어 native 프로세스가 실행된 것은 확인했습니다. 앱 종료 전 저장 hook과 폴더 선택 UI는 구현했으나 native 상호작용은 아직 별도 검증이 필요합니다.

## 컬럼 편집과 로고 보완

컬럼 헤더를 누르면 타입 설정을 엽니다. 텍스트·숫자·체크박스·날짜·선택·상태·URL을 지원하며, 행 이름(`title`)은 텍스트로 유지합니다. 적용 전 모든 행을 검사하고, 변환할 수 없는 값은 최대 8개 예시와 전체 실패 개수로 표시합니다. 선택지는 직접 지정하거나 기존 값에서 생성합니다. 숫자 변환은 정밀도와 표기가 바뀌는 입력을 거절하는 보수적인 규칙입니다. null과 미입력 값은 유지하고 숫자/체크박스로 바꿀 때 빈 문자열은 null로 변환합니다.

미리보기 revision은 스키마와 해당 DB 전체 행을 포함합니다. 검사 이후 행 추가·삭제·수정 또는 스키마 변경이 생기면 적용을 거절하고 명시적인 재검사를 요구합니다. 스키마와 변환된 행은 같은 복구 journal로 저장합니다. 105행 전체 변환, 기존 본문/노트 보존, 무효 입력의 전체 변경 차단, 동시 변경 충돌을 실제 임시 vault 테스트로 확인했습니다.

열 너비는 DB·vault별로 이 기기의 localStorage에 저장합니다. 헤더 경계 드래그, 방향키, 두 번 클릭/Home 초기화를 지원합니다. 본문 버튼은 이름 셀에 통합했습니다. 데이터 저장 모델은 행과 노트의 선택적 연결을 유지합니다. `database.property.edit` 명령(기본 leader `d t`)도 팔레트/단축키 설정에 등록합니다.

실제 CLI에 연결한 별도 임시 vault에서 헤더 클릭, 숫자/상태 타입 변환, 무효 값 차단, 드래그 후 260px 너비와 새로고침 복원, 키보드 10px 조절, 이름 셀의 기존 본문 열기와 새 본문 창 취소를 확인했습니다. 검사 후 CLI로 행을 수정하면 UI의 적용이 거절되고, ‘다시 검사’로만 재활성화되는 것도 확인했습니다. leader `d t`는 테스트 브라우저의 Vimium 키 처리와 충돌해 직접 전달한 DOM 키 이벤트로 해당 컬럼 창이 열리는 경로만 검증했습니다.

사이드바 로고·검색 행은 제거했습니다. 시작 화면의 로고는 유지하며, 내용 검색 메뉴와 기존 명령 팔레트 단축키는 계속 사용할 수 있습니다.

## Vault 하단 메뉴

Vault 선택은 상단 카드에서 사이드바 최하단의 44px 한 줄 메뉴로 옮겼습니다. 긴 노트/DB 목록은 별도 영역에서 스크롤됩니다. 브라우저에서 900×620 화면과 232px 사이드바에서도 메뉴가 하단에 남는 것, 최근 임시 vault 간 전환, 새 vault 생성 화면 열기를 확인했습니다. 실제 native 배치에 관한 검증 한계는 위와 같습니다.

## 폴더·휴지통·키보드·표 정리

노트 우클릭 메뉴에 열기·이름 변경·복제·내부 링크 복사·폴더 이동·휴지통 이동을 제공합니다. 노트 작업은 미저장 초안 저장이 성공한 뒤 실행하며, 외부 변경 충돌을 새 revision으로 덮어쓰지 않습니다. `leader r n`/F2는 포커스된 노트의 이름을 바꿉니다. 폴더와 하위 폴더를 만들고 이름을 바꿀 수 있으며, 삭제는 빈 폴더에만 허용합니다. 노트 이동·폴더 이름 변경 뒤 UUID·본문·링크 보존과 폴더 백업 roundtrip을 검증했습니다. 원본은 UUID 파일을 유지하고 앱의 폴더는 metadata로 분류합니다.

휴지통은 workspace snapshot을 직접 표시하므로 앱 내부 삭제/복원 완료 직후 함께 갱신됩니다. 휴지통 화면을 유지한 상태에서 사이드바 노트 삭제/복원, CLI 외부 삭제 반영(기존 3초 polling), DB 행 삭제/복원을 확인했습니다. DB 우측 삭제 전용 열을 없애고 행 번호 자리의 메뉴/우클릭으로 옮겼으며, 헤더·행 세로선을 맞췄습니다. 새 Vault 창은 체크박스 아래 26px 간격과 우측 버튼 정렬을 사용합니다. 타임라인 hover/focus에는 배경과 마커 강조를 적용했습니다.

브라우저의 실제 Ctrl 키 입력으로 좌우 패널, 위아래 영역 이동과 Ctrl+Shift+H 사용자 설정의 재실행 후 적용을 확인했습니다. 일반 hjkl은 브라우저에서 전달되지 않아 DOM 키 이벤트로 별도 검증했습니다: j/k 항목 이동, h 부모/접기, l 펼치기/열기, leader r n 포커스 노트 이름 변경, Vim OFF일 때 j를 소비하지 않음. 이 결과는 native IME/키보드 검증을 대신하지 않습니다. `test-results/workspace-QA.md`와 스크린샷에 확인 범위를 기록했습니다.

## 상단 정리와 노트 드래그 이동

사이드바의 로고·검색 헤더 행을 제거했습니다. 시작 화면 로고는 유지합니다. macOS에서는 native 창 버튼과 겹치지 않도록44px의 창 조작 영역만 확보하고, 다른 환경에서는8px 여백 뒤 탐색 메뉴를 표시합니다. 내용 검색 메뉴와 기존 팔레트 단축키는 유지합니다. 실제 native 창 배치·드래그 검증 한계는 위와 같습니다.

노트를 폴더에 드롭하면 해당 폴더로, NOTES 제목에 드롭하면 최상위로 이동합니다. 드래그 중 최상위 안내와 대상 강조를 표시하고, 이동 성공 후 접힌 대상 폴더를 펼칩니다. 같은 위치의 드롭은 쓰지 않고, 현재 vault 트리에서 시작한 드래그만 수용합니다. 이동은 `useNoteActions.moveTo` -> `moveNoteToFolder` -> core `note.update`를 거쳐 기존 이동 메뉴와 같은 조건부 저장 경로를 사용합니다. 드롭 시 화면의 note revision을 사용하며, 현재 편집 중인 노트는 초안을 먼저 저장합니다. 저장 실패/충돌이면 위치와 초안을 보존하고 새 revision으로 자동 재시도하지 않습니다.

Windows에서도 HTML5 내부 드래그가 동작할 수 있도록 Tauri의 OS 파일 drop 처리(`dragDropEnabled`)를 끄고 frontend가 처리합니다. 현재 연결된 파일 import drop 기능은 없습니다. 브라우저의 신뢰된 dragstart/over/drop/end 이벤트로 폴더·상위 폴더·최상위 이동을 확인했습니다. native 플랫폼의 실제 드래그는 별도 확인이 필요합니다. 추가 테스트3개는 dirty 저장 후 folderId만 변경, 저장 실패/동일 위치 무쓰기, 충돌 단일 요청을 검사합니다.

## 모든 노트 목록과 백링크 패널 정리

사이드바의 ‘모든 노트’는 `all-notes` 화면으로 이동합니다. 기존 `notes` 편집 화면과 분리하며 `view.notes` 명령과 leader `v n`도 전체 목록을 엽니다. 제목 검색, 지정 폴더에 직접 속한 노트 필터, 최근 수정/생성순과 제목순 정렬을 제공합니다. 하위 폴더는 전체 경로로 따로 선택하고, Vault 최상위도 선택할 수 있습니다. 폴더 선택 중 새 노트를 만들면 해당 위치를 기본값으로 사용합니다. 휴지통 항목은 목록에 포함하지 않습니다.

`AllNotesView`는 workspace snapshot에서 목록을 계산하며 별도 데이터 캐시나 저장 경로를 만들지 않습니다. 목록 조건은 노트/다른 화면을 열었다가 돌아와도 유지되고 Vault 전환 시 초기화합니다. 선택한 폴더가 삭제되면 전체로 표시합니다. 화살표/Home/End, Enter 열기, Vim ON의 j/k를 지원하며 검색칸에서 ↓를 누르면 첫 결과로 이동합니다. 우클릭·더보기 메뉴와 F2/leader r n은 기존 노트 관리 경로를 재사용합니다.

백링크 패널 하단의 장식용 문구·아이콘·구분선을 제거했습니다. 들어오는/나가는 링크 목록과 링크가 없을 때의 간단한 안내는 유지합니다. 신규 테스트 4개는 전체 폴더 포함·원본 배열 보존·검색과 폴더 조합·정렬·snapshot 변경 반영을 검사합니다.

임시 Workspace QA vault에서 전체 5개 노트와 중첩 폴더 경로, 폴더/제목 조합 필터, 빈 결과 초기화, 날짜/제목 정렬, 검색칸 ↓와 Enter 열기, 필터 유지, Shift+F10 메뉴, F2 이름 변경, 삭제 직후 목록·개수 갱신을 확인했습니다. 새 노트를 선택 폴더에 만들고 dirty 상태에서 목록으로 전환한 뒤 본문이 저장된 것도 실제 코어에서 확인했습니다. 팔레트의 ‘모든 노트 열기’ 실행과 900×620 어두운 테마에서 가로 넘침이 없는 배치를 확인했습니다. j/k는 브라우저 확장 간섭 때문에 DOM 키 이벤트로 Vim ON/OFF 분기만 검증했으며 native 키/IME 검증으로 계산하지 않습니다. `test-results/all-notes-QA.md`에 기록했습니다.

## 인라인 이름 변경과 키 입력 설정

사이드바 노트·폴더 이름 변경은 선택한 행의 입력칸으로 전환합니다. 상단 새 폴더 버튼은 Vault 최상위에 폴더를 먼저 만들고 이름 입력으로 들어갑니다. 폴더 우클릭의 새 노트/하위 폴더도 해당 위치에 즉시 생성하며, 접힌 부모는 이름 입력을 위해 펼칩니다. Enter/포커스 이동으로 저장하고 Esc로 이름 편집을 취소합니다. 새 항목에서 Esc를 누르면 이미 생성된 기본 이름의 항목은 남습니다. 폴더의 같은 이름 충돌과 revision 충돌은 입력칸에서 표시하며 자동 덮어쓰기를 하지 않습니다. 이동/삭제 등 기존 대화상자는 유지합니다.

파일 트리의 별도 점 세 개 버튼을 제거했습니다. 행 전체로 선택·포커스를 표시하며 우클릭 또는 Shift+F10으로 관리 메뉴를 엽니다. Vim ON의 j/k는 노트·폴더·데이터베이스만 순회하고 생성·설정 등의 버튼을 건너뜁니다. h/l은 폴더 접기·펼치기·부모/자식 이동과 파일 열기를 담당합니다. F2와 leader r n은 포커스된 노트 또는 폴더 이름을 인라인으로 바꿉니다.

설정의 보기 모드 선택 행을 label에서 분리해 설명/빈 여백 클릭으로 드롭다운이 열리지 않게 했습니다. Leader 키는 실제 키나 조합을 기록합니다. 입력 중 전역 명령 실행을 막고, 기존 일반 단축키 충돌은 저장 전에 표시합니다. Esc/Tab/취소는 기존 설정을 유지하며, 예전 Space·쉼표·역슬래시 설정도 계속 읽습니다. 일반 단축키와 leader 뒤의 명령 조합 입력은 기존 방식을 유지합니다.

## Vim 커서 표시

Vim 라이브러리의 높은 우선순위 테마가 앱의 커서 색상을 덮어쓰고, 편집기가 포커스를 잃으면 빨간 outline을 표시했습니다. 커서 레이어에 한정한 스타일로 테마 색상을 적용하고 outline을 제거했으며, 편집기에서 포커스를 벗어나면 Vim 커서 레이어를 숨깁니다. 일반 입력 커서와 Visual selection은 유지합니다. 코드 자체나 Markdown 원본을 바꾸는 수정은 아닙니다.

브라우저의 실제 CLI 연결 UI에서 인라인 생성/이름 변경, Leader 기록/충돌 차단, Vim 트리 이동과 커서 스타일을 확인했습니다. 브라우저가 일부 물리 Vim 키를 가로채므로 해당 경로는 DOM KeyboardEvent로 검증했습니다. macOS WebView의 간헐적 잔상과 실제 한글 IME 검증을 완료했다고 주장하지 않습니다. 추가 기록은 `test-results/readable-links-QA.md`를 참고하세요.


## 오른쪽 패널 포커스·한글 명령 키·Leader 대기

오른쪽 패널의 Vim j/k와 영역 이동은 열 수 있는 백링크·outgoing link만 대상으로 합니다. 선택을 테마 배경과 테두리로 강조하고 스크롤을 따라갑니다. h는 현재 링크를 유지하며 l은 엽니다. 링크 목록 갱신은 기존 선택을 유지하고 선택한 대상이 사라지면 인접 링크로 이동합니다. 마지막 링크가 사라지면 본문 재로딩 중에도 유지되는 본문 영역에 포커스를 둡니다. 빈 패널 진입은 현재 포커스를 유지합니다.

한글 입력 소스의 비ASCII/Process/Unidentified 키는 명령 문맥에서 code와 Shift로 해석합니다. Ctrl+h/j/k/l은 조합 중에도 영역 이동을 실행하고, 다른 일반 명령은 실제 본문 조합을 방해하지 않습니다. Vim Normal/Visual에서는 CodeMirror의 composing 차단보다 먼저 명령을 전달합니다. Insert 모드, f/r의 문자 인수, Meta/Alt 입력은 이 변환을 거치지 않습니다. OS 입력 소스 자체는 변경하지 않습니다.

기본 키 표기는 소문자이며 Ctrl+h와 Ctrl+H를 각각 지정할 수 있습니다. Ctrl+H와 Ctrl+Shift+h는 같은 조합이므로 중복을 거절합니다. Leader 뒤의 r/R도 구분합니다. Core가 버전 없는 기존 설정의 대문자를 과거 의미대로 변환해 반환하고 다음 설정 저장에서 shortcutVersion 2를 기록합니다. 읽기만으로 파일을 다시 쓰지 않습니다. 신규 버전을 모르는 구버전 앱으로의 downgrade는 지원하지 않습니다.

Leader의 1.8초 타이머를 제거했습니다. 시작 키 또는 중간 조합 입력 뒤 시간이 지나도 대기하며 안내에 Esc 취소를 표시합니다. 명령 실행·Esc·미등록 조합·창 포커스 이탈 시 해제합니다.

임시 Focus IME QA vault에서 오른쪽 링크만 순회·선택 삭제 시 복원·새 링크 추가 시 선택 유지, 단축키 대소문자 저장/충돌, 한글 키 이벤트의 Vim i/a/o/I/A/O·Visual 모드·undo, f/r의 한글 인수를 확인했습니다. 브라우저 CDP로 ㅎ→하→한 조합과 한 번의 확정을 확인했습니다. Leader와 r 접두사를 각각 2.3초 기다린 후 n으로 인라인 이름 변경을 실행했습니다. 명령 라우팅은 DOM KeyboardEvent로 검사한 결과이며 macOS WebView의 실제 한국어 입력 소스·물리 키 검증을 대신하지 않습니다. 상세 기록은 test-results/focus-ime-QA.md에 있습니다.


## 폴더 우클릭 메뉴 색상

폴더 메뉴는 사이드바 안에서 렌더링되어 사이드바의 밝은 글자색을 상속하고 있었습니다. 공통 ContextMenu에 테마의 ink 색상을 명시해 노트 메뉴와 같은 색을 사용하게 했습니다. 아이콘도 같은 색을 따르고 삭제 항목의 강조색은 유지합니다. Paper와 Midnight에서 실제 노트/폴더 메뉴의 계산된 글자색을 비교하고 스크린샷으로 확인했습니다.


## 이름 변경 중 행 크기와 글자 위치 유지

일반 파일 행과 인라인 이름 입력이 같은 grid·글꼴 크기·여백을 사용합니다. 입력칸의 별도 border/padding을 제거하고 행 안쪽 outline으로 편집 테두리를 표시해 기존 글자 위치에서 바로 수정합니다. 접힌 폴더의 펼침 아이콘도 편집 중 유지합니다. 이름 오류는 행 아래에 겹쳐 표시하며 트리 행 높이를 늘리지 않습니다.

임시 Rename Layout QA vault의 최상위 노트·폴더·하위 폴더·중첩 노트에서 편집 전후 행·아이콘·글자 영역 좌표와 모든 이웃 행 좌표가 동일함을 확인했습니다. 기존 35.5→37.5px 높이 변화와 글자 시작점 5px 이동이 사라졌습니다. Enter 저장·Esc 취소·중복 폴더 오류, 200px 사이드바의 긴 이름과 Midnight 테마, 새 폴더 입력도 확인했습니다. 검증 기록은 test-results/rename-layout-QA.md에 있습니다.


## DB 본문 관계와 노트 백링크 구분

DB 행의 bodyNoteId 소속 관계는 ‘연결된 생각’과 노트·타임라인의 연결 개수에서 제외합니다. 공통 noteLinks 함수로 실제 노트가 출처인 링크만 표시하며 제목이나 alias로 구분하지 않습니다. 본문에 명시한 자기 링크, 다른 노트의 참조, 미해결 링크, record 대상 위키링크는 유지합니다. DB 본문 열기와 원본 연결 데이터, 코어의 일반 관계 조회 계약은 변경하지 않았습니다.

회귀 테스트 2개로 자동 DB 관계 제외와 명시적 링크 보존을 검사했습니다. 임시 Body Backlinks QA vault에서 자동 관계만 들어오는 본문 노트가 백링크 0/나가는 링크 1/연결 수 1로 표시되는 것과, 다른 노트 참조·명시적 자기 링크를 추가하면 백링크 2/나가는 링크 2/연결 수 3으로 갱신되는 것을 확인했습니다. 같은 기준을 타임라인에서도 검증했습니다. 기록은 test-results/body-backlinks-QA.md에 있습니다.

### Vault 이름과 저장 위치

새 Vault 팝업과 첫 실행 화면에서 이름을 바꾸면 저장 경로의 마지막 폴더명이 함께 바뀝니다. 현재 Vault, 없으면 최근 Vault의 상위 위치를 사용하고, 이력이 없으면 core가 제안한 기본 위치를 사용합니다. 폴더 선택으로 상위 위치를 변경할 수 있고 전체 경로를 직접 입력한 경우에는 해당 경로를 유지합니다. 폴더 선택 버튼을 경로 입력창 우측에 붙였습니다. 기존 Vault 열기는 선택한 폴더를 그대로 열며 생성용 경로와 섞이지 않습니다.

임시 Vault에서 이름 변경·직접 경로 유지·선택 취소·다른 상위 위치 선택·실제 생성·다음 Vault의 위치 제안을 확인했습니다. Welcome의 최근 위치·기존 Vault 열기와 지연된 기본 위치 응답의 입력 보존도 확인했습니다. 밝은 테마와 900×620 어두운 테마에서 경로 입력과 버튼의 높이/경계가 일치하며 가로 넘침이 없습니다. 브라우저 QA에서는 native 폴더 선택 결과만 대체했고, 생성/열기는 실제 CLI 코어를 사용했습니다. OS 폴더 대화상자 자체의 조작은 검증하지 않았습니다. `npm test`, `npm run check`, macOS debug bundle이 통과했으며 기록은 `test-results/vault-location-QA.md`에 있습니다.
