# Foltra 0.1.0-preview.9

**플러그인 사용에 한 번 동의하면, 이후에는 설치하고 켜기만 하면 됩니다.**

[**macOS DMG 다운로드**](https://github.com/snacky101/foltra/releases/download/v0.1.0-preview.9/Foltra_0.1.0-preview.9_aarch64.dmg) · [처음 사용하는 분을 위한 안내](https://github.com/snacky101/foltra/blob/v0.1.0-preview.9/README.md)

## 무엇이 달라졌나요?

플러그인을 도구 상자라고 생각하면 됩니다. 먼저 **플러그인 사용**을 켜고 한 번 동의합니다. 그 뒤에는 Anki나 캘린더처럼 필요한 도구만 설치해서 켜면 됩니다.

| 상황                     | 이전                     | 이번 버전                                    |
| ------------------------ | ------------------------ | -------------------------------------------- |
| 플러그인 사용 시작       | 플러그인마다 권한 확인   | 전체 사용을 켤 때 최초 한 번 동의            |
| 다른 플러그인 추가       | 설치 후 개별 동의·활성화 | 설치 후 활성화                               |
| 껐던 플러그인 다시 켜기  | 다시 권한 확인           | 바로 활성화                                  |
| 앱에서 플러그인 업데이트 | 다시 동의·활성화         | 기존 활성화 상태 유지                        |
| 전체 플러그인 잠시 끄기  | 각각 비활성화            | 전체 스위치로 끄고, 다시 켜면 기존 선택 복원 |

확장별 **사용하는 권한**은 접을 수 있는 목록에서 확인합니다. 권한 제한과 실행 격리는 그대로 유지합니다. 테마 설치에는 이 동의가 필요하지 않습니다.

## 업데이트 후 한 번만 해주세요

1. **설정 → 확장**을 엽니다.
2. **플러그인 사용**을 켜고 **동의하고 사용**을 누릅니다.
3. 이전에 활성화했던 플러그인이 다시 실행됩니다. 새 플러그인은 설치하고 활성화하세요.

> [!IMPORTANT]
> 동의는 **현재 기기·vault별**로 기억합니다. 다른 vault나 새 기기에서는 처음 한 번 동의해야 합니다. 기존 개별 활성화 선택과 플러그인 설정·데이터는 보존합니다.

## 읽기 쉬워진 사용 안내

README를 다운로드부터 첫 노트 작성까지 따라갈 수 있도록 다시 정리했습니다. Vault·링크·데이터베이스를 쉬운 예로 설명하고, 기능표·단축키표·짧은 명령 예제를 넣었습니다. 긴 빌드·캐시 설명은 개발 안내로 옮겼습니다.

## 설치와 업데이트

- **이미 사용 중이라면:** 설정 → **앱 업데이트**에서 확인하세요. 업데이트 기능이 없는 `preview.1`은 DMG로 한 번 수동 설치합니다.
- **처음 설치한다면:** 위의 DMG를 열고 `Foltra.app`을 `Applications`로 옮기세요.
- **CLI를 쓴다면:** 앱에 CLI가 포함됩니다. 설정 → **CLI → CLI 설치**로 터미널 명령을 연결하세요. 이미 연결했다면 앱과 함께 갱신됩니다.

현재 설치 파일은 **Apple Silicon Mac용 개발 프리뷰**입니다. Apple Developer ID 서명·공증은 아직 없습니다. 첫 실행이 차단되면 다운로드 출처를 확인한 뒤 [Apple의 실행 안내](https://support.apple.com/guide/mac-help/mh40616/mac)를 참고하세요.

## 검증과 범위

최초 동의 저장, 여러 플러그인 활성화, 전체 끄기·복원, 업데이트 후 상태 유지, 오래된 요청 차단을 검사했습니다. 로컬 전체 테스트 **1,743개**와 정적 검사를 통과했고, 마지막 실패 처리 보완은 관련 UI **26개** 검사로 확인했습니다. 실제 CLI를 매번 새 프로세스로 실행해 동의 상태가 유지되는 것도 확인했습니다.

최종 설정 화면의 수동 클릭·시각 검증과 실제 설치 앱에서의 업데이트 완료 검증은 이번 로컬 검사에 포함되지 않았습니다. 정확한 배포 커밋은 GitHub Actions에서 다시 검사한 뒤 게시합니다.
