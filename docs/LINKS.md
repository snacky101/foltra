# 제목 링크와 alias

노트의 내부 UUID와 파일 경로는 유지하고, Markdown에는 읽기 쉬운 제목 링크를 저장합니다.

```markdown
[[노트이름]]
[[노트이름|foo]]
[[노트이름#^anchor|근거]]
```

`|` 앞은 연결 대상, 뒤는 표시 이름입니다. `foo`라는 별도 노트가 있어도 두 번째 링크의 대상은 `노트이름`입니다. 첫 번째 `|` 뒤의 사용자 입력은 그대로 보존합니다. 읽기 모드와 Live Preview에서 alias를 표시하며 주제 모음과 백링크는 실제 대상 노트로 묶습니다.

## 저장과 이름 변경

- 제목이 vault 안에서 유일하면 `[[제목]]`을 사용합니다. 링크 삽입과 링크 복사도 core의 읽기 전용 `note.link` 명령으로 같은 문자열을 얻습니다.
- 앱/CLI로 이름을 바꾸면 활성 노트의 참조도 같은 저장 journal에서 갱신합니다. `[[이전이름|foo]]`는 `[[새이름|foo]]`가 됩니다. 제목 변경 전에 작성한 오래된 revision으로 참조 노트를 저장하면 충돌로 거절합니다.
- 코드 펜스·인라인/들여쓴 코드, HTML 주석, 이스케이프한 링크 예제, 일반 Markdown 링크의 URL은 바꾸거나 백링크로 인덱싱하지 않습니다. 원문 소스 범위를 사용하여 관련 없는 공백과 줄바꿈을 보존합니다.
- 기존 `[[UUID|표시 이름]]`도 계속 해석합니다. 단순 열기/조회로 파일을 바꾸지 않습니다. 해당 노트를 수정·저장할 때 유일한 제목으로 줄이되, 기존 alias는 보존합니다. 과거 자동 생성된 alias와 사용자가 지정한 alias는 구별할 수 없으므로 `[[제목|제목]]`도 임의로 삭제하지 않습니다.
- 메타데이터·UUID 파일명·백업 형식은 바꾸지 않습니다. 링크 대상 변경으로 영향을 받는 노트 본문과 revision은 갱신됩니다.

## 모호한 제목과 삭제

동명 노트는 허용하지만 제목만으로 임의의 노트를 선택하지 않습니다. 제목 중복, `[]|#`·역슬래시·줄바꿈이 포함된 제목, 예약된 `record:` 이름처럼 제목을 대상으로 사용하기 어려운 경우에는 `[[UUID|표시 이름]]`을 사용합니다. 표시 이름에 링크 종료 문자가 들어가지 않도록 생성 시 정리합니다. 같은 철자의 노트 제목이 생겨도 UUID 대상이 우선합니다. 폴더는 현재 분류용 metadata이며 `[[폴더/제목]]` 경로 해석은 아직 제공하지 않습니다.

동명 노트가 추가되거나 이름이 중복되도록 변경되면, 이미 연결된 참조는 원래 노트의 UUID로 바꾸어 대상을 보존합니다. 노트를 삭제할 때도 들어오는 참조를 UUID로 유지하여 나중에 동명 노트를 만들어도 연결이 바뀌지 않습니다. 휴지통 안의 원본은 나가는 링크를 UUID로 보관하므로 복원 전 대상 이름이 바뀌어도 연결할 수 있습니다. 복원은 현재 활성 제목을 기준으로 다시 표현합니다. DB 행에서 새 본문 노트를 만드는 경로도 동일한 저장 계획을 사용합니다.

기존에 미해결이거나 중복으로 모호했던 제목 링크는 변경 전 대상을 추정해 고정하지 않습니다. 이후 제목이 유일해지면 해당 노트로 해석될 수 있습니다.

## CLI와 구현 경계

```sh
foltra --vault /path/to/vault note link --id NOTE_UUID
```

명령은 JSON 문자열 `"[[노트이름]]"` 또는 필요한 경우 UUID와 표시 이름을 반환합니다. 저장·이름 변경은 기존 `note.create` / `note.update` 명령을 사용합니다.

`wiki.rs`가 Markdown 링크 범위, 제목/ID 해석, 표시 문자열과 대상 갱신을 담당합니다. `notes::plan_note_write`가 변경 전후 대상을 비교하고 노트/참조 쓰기 목록을 만든 뒤, 호출자가 필요한 레코드·휴지통 쓰기와 함께 한 번에 commit합니다. 일반 본문 수정에서는 다른 노트 본문을 재작성하지 않습니다.

외부 편집기가 metadata 제목을 직접 바꾸는 경우에는 자동 참조 갱신을 보장하지 않습니다. Git 동시 변경 병합, 대형 vault의 이름 변경 성능, native IME는 별도 검증 대상입니다.
