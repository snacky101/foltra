# 제목 링크와 alias

노트의 내부 UUID와 파일 경로는 유지하고, Markdown에는 읽기 쉬운 제목 링크를 저장합니다.

```markdown
[[노트이름]]
[[노트이름|foo]]
[[노트이름#^anchor|근거]]
```

`|` 앞은 연결 대상, 뒤는 표시 이름입니다. `foo`라는 별도 노트가 있어도 두 번째 링크의 대상은 `노트이름`입니다. 첫 번째 `|` 뒤의 사용자 입력은 그대로 보존합니다. 읽기 모드와 Live Preview에서 alias를 표시하며 주제 모음과 백링크는 실제 대상 노트로 묶습니다.

## 자동완성과 미생성 노트

Live Preview와 원문 모드에서 `[[`을 입력하면 노트 제목 자동완성이 열립니다. ↑/↓로 이동하고 Enter 또는 Tab으로 선택하면 `]]`까지 입력하고 커서를 링크 뒤로 옮깁니다. 이미 있는 닫는 괄호는 중복하지 않으며 `|별칭`과 `#^블록`은 보존합니다. 같은 제목의 노트는 구분 정보를 표시하고 UUID 대상과 제목 alias를 입력합니다. Vim에서는 Insert 모드에서 사용하며 코드·이스케이프 예제에는 자동완성을 열지 않습니다.

새 제목을 선택해도 링크만 작성합니다. 읽기 모드·연결 목록·Live Preview의 표시된 링크에서는 클릭, 원문에서는 Cmd/Ctrl+클릭이나 커서 위치에서 Cmd+Enter(macOS)/Ctrl+Enter(그 외)로 열 때 실제 빈 노트를 만듭니다. Vim Normal의 `gd`는 기존 노트로만 이동하며 대상이 없으면 아무 동작도 하지 않습니다. 그래프는 기존 노드처럼 두 번 클릭하거나 Enter로 엽니다. 생성 직후 기존 참조가 해당 노트의 백링크로 연결됩니다. 같은 대상을 연속·동시에 열어도 한 노트만 생성하며, 모호한 제목이나 삭제된 UUID 대상을 임의의 새 노트로 대체하지 않습니다.

설정 → 편집 → **미생성 노트 표시**는 기본 ON입니다. 그래프에 생성 가능한 제목 대상을 점선 노드로 표시하고, 연결 목록·자동완성에도 미생성 링크를 포함합니다. alias가 달라도 실제 제목이 같으면 그래프에서 하나로 묶습니다. OFF는 이 표시만 숨기며 본문의 링크와 새 제목 입력·클릭 생성은 유지합니다. 설정은 Vault별로 저장하고 기존 설정 파일에 항목이 없어도 ON으로 읽습니다.

## 커서 위치에서 링크 열기

Live Preview와 원문에서 `[[대상|별칭]]`의 대상·별칭·괄호 위에 커서를 놓고 `Cmd+Enter` 또는 Vim Normal의 `gd`로 대상 노트를 엽니다. `gd`는 Leader 없이 연속으로 입력하며 Insert에서는 평소처럼 문자를 입력합니다. `gd`는 `note.follow-existing-link`(커서 위치의 링크 열기, 노트 생성 안 함), `Cmd+Enter`는 `note.follow-link`(커서 위치의 링크 열기 / 없는 노트 만들기)의 기본값입니다. 기존 노트는 두 명령 모두 열지만 미생성 대상은 `Cmd+Enter`만 생성하며, 두 명령의 단축키를 각각 설정할 수 있습니다. 설정 → 단축키의 키 조합 입력란에 `gd` 또는 `<leader>gd`처럼 적습니다. `<leader>`를 붙이면 Leader 이후에 입력하는 조합이 됩니다. 일반 단축키는 별도 입력란에서 수정하며, 조합을 비우거나 삭제한 뒤 저장하면 해제됩니다.

노트를 열 때는 기존 클릭과 동일하게 초안을 먼저 저장합니다. `gd`에서 대상이 없거나 제목이 모호하면 저장·생성·이동 기록 변경 없이 현재 위치에 머뭅니다. 코드·이스케이프 예제·일반 텍스트·링크 뒤 공백에서는 이동하지 않고 여러 커서나 조합 입력 중에는 열기를 실행하지 않습니다. 블록 위치 이동은 아직 제공하지 않습니다.

## Markdown 웹 링크와 Live Preview 클릭

`[표시 이름](https://example.com)`의 이름·URL·괄호 안에 커서를 놓으면 `gd`와 `Cmd+Enter` 모두 기본 브라우저로 엽니다. `http`, `https`, `mailto`를 지원하며 괄호가 포함된 URL, 선택적 제목, Markdown 이스케이프와 HTML 엔티티도 해석합니다. 원문 모드의 Cmd/Ctrl+클릭과 읽기 모드의 클릭도 같은 열기 경로를 사용합니다. 데스크톱은 Tauri opener의 제한된 URL 권한을 사용하며 열기 실패를 화면에 표시합니다.

Live Preview에서는 커서나 선택 범위가 링크 안에 있을 때만 원문을 표시합니다. 같은 줄의 다른 부분을 편집 중이어도 링크는 렌더링 상태를 유지하며 일반 클릭으로 열립니다. 방향키·Vim 이동으로 링크 안에 들어가거나 Shift+클릭으로 선택 범위를 확장하면 원문을 편집할 수 있습니다. 코드 예제와 이미지 URL은 링크 열기의 대상이 아닙니다.

상대 경로 Markdown 링크의 노트 해석, `file:`·사용자 정의 프로토콜, 페이지 내부 `#anchor` 이동은 아직 지원하지 않습니다. 이런 대상은 실행하지 않으며 노트 연결에는 기존 `[[노트 이름]]`을 사용합니다. Markdown 웹 링크는 노트 백링크나 지식 그래프에 포함하지 않습니다.

## 저장과 이름 변경

- 제목이 vault 안에서 유일하면 `[[제목]]`을 사용합니다. 팔레트의 링크 삽입과 링크 복사는 core의 읽기 전용 `note.link` 명령으로 같은 문자열을 얻으며, 편집기의 자동완성도 같은 대상/alias 규칙을 따릅니다.
- 앱/CLI로 이름을 바꾸면 활성 노트의 참조도 같은 저장 journal에서 갱신합니다. `[[이전이름|foo]]`는 `[[새이름|foo]]`가 됩니다. 제목 변경 전에 작성한 오래된 revision으로 참조 노트를 저장하면 충돌로 거절합니다.
- 코드 펜스·인라인/들여쓴 코드, HTML 주석, 이스케이프한 링크 예제, 일반 Markdown 링크의 URL은 바꾸거나 백링크로 인덱싱하지 않습니다. 원문 소스 범위를 사용하여 관련 없는 공백과 줄바꿈을 보존합니다.
- 기존 `[[UUID|표시 이름]]`도 계속 해석합니다. 단순 열기/조회로 파일을 바꾸지 않습니다. 해당 노트를 수정·저장할 때 유일한 제목으로 줄이되, 기존 alias는 보존합니다. 과거 자동 생성된 alias와 사용자가 지정한 alias는 구별할 수 없으므로 `[[제목|제목]]`도 임의로 삭제하지 않습니다.
- 메타데이터·UUID 파일명·백업 형식은 바꾸지 않습니다. 링크 대상 변경으로 영향을 받는 노트 본문과 revision은 갱신됩니다.

## 모호한 제목과 삭제

동명 노트는 허용하지만 제목만으로 임의의 노트를 선택하지 않습니다. 제목 중복, `[]|#`·역슬래시·줄바꿈이 포함된 제목, 예약된 `record:` 이름처럼 제목을 대상으로 사용하기 어려운 경우에는 `[[UUID|표시 이름]]`을 사용합니다. 표시 이름에 링크 종료 문자가 들어가지 않도록 생성 시 정리합니다. 같은 철자의 노트 제목이 생겨도 UUID 대상이 우선합니다. 폴더는 현재 분류용 metadata이며 `[[폴더/제목]]` 경로 해석은 아직 제공하지 않습니다.

동명 노트가 추가되거나 이름이 중복되도록 변경되면, 이미 연결된 참조는 원래 노트의 UUID로 바꾸어 대상을 보존합니다. 노트를 삭제할 때도 들어오는 참조를 UUID로 유지하여 나중에 동명 노트를 만들어도 연결이 바뀌지 않습니다. 휴지통 안의 원본은 나가는 링크를 UUID로 보관하므로 복원 전 대상 이름이 바뀌어도 연결할 수 있습니다. 복원은 현재 활성 제목을 기준으로 다시 표현합니다. DB 행에서 새 본문 노트를 만드는 경로도 동일한 저장 계획을 사용합니다.

기존에 미해결이거나 중복으로 모호했던 제목 링크는 변경 전 대상을 추정해 고정하지 않습니다. 이후 제목이 유일해지면 해당 노트로 해석될 수 있습니다.

## CLI와 구현 경계

```sh
foltra --vault /path/to/vault note link --id NOTE_UUID
foltra --vault /path/to/vault note open-link --target '노트이름'
```

`note.link`는 JSON 문자열 `"[[노트이름]]"` 또는 필요한 경우 UUID와 표시 이름을 반환합니다. 저장·이름 변경은 기존 `note.create` / `note.update` 명령을 사용합니다.

`note.open-link`는 기존 노트를 반환하거나 없는 제목의 빈 노트를 만들어 반환하는 쓰기 명령입니다. 대상 해석과 생성은 같은 vault 잠금 아래에서 실행합니다. 링크 조회 결과에는 해석된 UUID인 `target`, 원래 대상 이름인 `name`, 표시 이름인 `label`을 분리해 반환합니다. 이 필드는 파생 조회 결과이며 노트 원본 포맷을 변경하지 않습니다.

`wiki.rs`가 Markdown 링크 범위, 제목/ID 해석, 표시 문자열과 대상 갱신을 담당합니다. `notes::plan_note_write`가 변경 전후 대상을 비교하고 노트/참조 쓰기 목록을 만든 뒤, 호출자가 필요한 레코드·휴지통 쓰기와 함께 한 번에 commit합니다. 일반 본문 수정에서는 다른 노트 본문을 재작성하지 않습니다.

외부 편집기가 metadata 제목을 직접 바꾸는 경우에는 자동 참조 갱신을 보장하지 않습니다. Git 동시 변경 병합, 대형 vault의 이름 변경 성능, native IME는 별도 검증 대상입니다.
